## 2. What was done on 2026-08-11

### App Store config (was going to ship a dead app)
- **`eas.json` `production` was `{}`** — no env. `_layout.tsx` guards on `if (url && anonKey)`,
  so a production build never called `initSupabase()` and `getSupabase()` threw on the first
  query. It would have installed, launched, and been an empty shell. `production` and `preview`
  now carry Supabase + Stripe vars.
- **Icons** generated from the previously-unused `design_handoff_noot_app/app/brand/appicon.png`
  into `apps/mobile/assets/`. `icon.png` is deliberately **RGB with no alpha** — App Store
  Connect rejects a transparent icon.
- **Version** `1.0.0`, `ios.buildNumber 1`, `android.versionCode 1`, `autoIncrement` on.
- **`RECORD_AUDIO` + `CAMERA` removed.** Note for whoever revisits this: deleting them from
  `app.json` does nothing. `expo-image-picker`'s config plugin re-adds both, plus the iOS
  mic/camera usage strings, unless you set `"cameraPermission": false` and
  `"microphonePermission": false`. The app is photo-library-only.
- **`pnpm check:release`** (`scripts/check_release.mjs`) is a preflight that fails on all of the
  above. Verified by restoring the old config and watching it catch 5 blockers.

### Legal pages
- `/privacy` and `/terms` on the marketing site, linked from the site footer and in-app
  (Profile → Privacy Policy / Terms of Service). The privacy page documents the deletion
  behaviour below; keep the two in sync if deletion changes.
- The in-app links point at `https://noot.app/privacy|terms`. **Those must be live at that
  domain before submission** — Apple's reviewers open the privacy URL directly.

### The marketing site could not build at all
`node-linker=hoisted` (required for Expo autolinking) meant Next 14 resolved its own nested
React 18 while the workspace hoists React 19 for React Native — two React copies, and the
`/404` + `/500` prerender crashed with `Cannot read properties of null (reading 'useContext')`.
Fixed by moving `apps/web` to **Next 15 + React 19**, matching the rest of the monorepo. Single
React instance now. This had nothing to do with the new pages; it was pre-existing and would
have blocked deploying the privacy policy.

### Account deletion — App Store Guideline 5.1.1(v)
There was no deletion route at all, which is one of the most common rejection causes.

The design is **revoke the identity, de-identify the record**:
- `auth.users` row is deleted → sign-in returns "Invalid login credentials"
- `public.users` row is **kept**, stripped of name/email/photo/courses, `deleted_at` set
- completed bookings and payouts survive, joined to an anonymous row

**Why:** `users.id` referenced `auth.users(id) ON DELETE CASCADE`, and `bookings.student_id` /
`tutor_id` cascade from `users`. Deleting the auth identity would have destroyed the payment
history we must retain for tax and chargebacks. **Migration `0026` drops that FK** so the two
can happen independently.

The deliberate trade-off: deleting a user straight from the Supabase Auth dashboard now leaves
an orphaned app row instead of silently destroying financial history. If orphans accumulate,
that's the cause.

Pieces: `0026_account_deletion.sql`, `supabase/functions/delete-account/index.ts`,
`api.profile.deleteAccount()`, Profile → Delete account (confirm dialog states the retention).
Refuses with 409 if a `pending`/`confirmed` booking is still live.

### Production-readiness cleanup
- **`devSignIn` deleted from `@noot/core`.** It was *"sign in **or silently create the
  account**"* and shipped in the production bundle. It also caused a false test failure by
  re-creating an account that had just been deleted. All eight verify scripts now use
  `auth.signInWithPassword`.
- **All `__DEV__` shortcuts removed** from the signup screen (dev sign-in buttons, skip-email
  -verification link). `grep -rn "__DEV__" apps/mobile` is now empty.
- **"Sign out" never signed out** — it only called `router.replace('/')`, so the session
  survived and relaunching dropped you back in as the same user. Now calls `auth.signOut()`.
- **A tutor could see and book themselves.** `api.tutors.search()` now excludes the signed-in
  user. Done in core so every caller inherits it.
- **A deleted tutor stayed in search** — search filtered on `approval_status` only, and a
  deleted tutor keeps an approved `tutor_profiles` row. Now also filters `deleted_at is null`.
- **The cancel screen had a fabricated refund selector** (`xsc.tsx`) letting the student tap
  between refund tiers, "· demo". In a screen about money that implied a choice that doesn't
  exist and could show a full refund on a session starting in an hour. The tier is now derived
  from the real `scheduledAt` and rendered read-only; the server's refund percent remains
  authoritative.
- `tutor_calendar.tsx` comments claimed a "demo fallback" — there was none, the grid starts
  empty. Comments corrected rather than pretending data was removed.

## 3. JADIN'S LIST — nobody else can do these

Each one needs an account, a credential, a domain, or a physical device. No amount of code
work moves them. They are the actual critical path to submission.

### 3a. Create the app in App Store Connect
Bundle ID **`com.noot.app`** (already set in `app.json`; must match exactly). Doing this is what
produces the `ascAppId` needed below.

### 3b. Fill in the submit credentials
`apps/mobile/eas.json` → `submit.production.ios` currently holds three placeholders:

```
"appleId":     "REPLACE_WITH_APPLE_ID_EMAIL",       // the Apple ID email you enrolled with
"ascAppId":    "REPLACE_WITH_APP_STORE_CONNECT_APP_ID",  // numeric, from the ASC app URL
"appleTeamId": "REPLACE_WITH_APPLE_TEAM_ID"          // 10 chars, developer.apple.com → Membership
```

`pnpm check:release` warns until all three are real.

### 3c. Deploy the marketing site to `noot.app`
`apps/web` builds clean now (`pnpm --filter @noot/web build`). It must be live because:
- **`https://noot.app/privacy`** goes in the App Store Connect privacy field, and reviewers
  open it directly. A 404 stalls review.
- The in-app Profile links point at `noot.app/privacy` and `noot.app/terms` — they are dead
  buttons until the domain resolves.
- Apple also requires a **support URL**; `noot.app` itself will do.

### 3d. Deploy the two Edge Functions and run their check
`approve-tutor` (rewritten — it now grants and withdraws the tutor role) and `delete-account`
(new) have **never executed anywhere**. The local edge runtime container has been unavailable
for several sessions, so they are the least-tested code in the repo and they decide who is a
tutor and whose account gets erased.

```
supabase functions deploy approve-tutor delete-account
pnpm dlx tsx scripts/verify_approve_tutor_fn.mts   # written, never run
```

### 3e. Configure SMTP in Supabase
Auth → Settings → SMTP. Without it, real `.edu` signup and password reset send nothing — and
the `__DEV__` bypass that made this survivable locally has been removed.

### 3f. Build and actually use the app
```
eas build --profile production --platform ios
eas submit --profile production --platform ios
```
Then **use it on a phone**. See §1 — this is the largest open risk in the project and one
TestFlight build retires all of it.

### 3g. App Store Connect metadata (none of this exists yet)
- Screenshots — 6.7" and 6.5" iPhone are mandatory
- Description, keywords, promotional text, category (Education)
- Age rating questionnaire
- Support URL + marketing URL
- **Privacy nutrition label.** Apple cross-checks it against the privacy policy, so answer it
  to match `/privacy` exactly. Based on what the app actually does:

  | Type | Data | Linked to user | Purpose | Tracking |
  |---|---|---|---|---|
  | Contact Info | Name, Email | Yes | App Functionality | No |
  | User Content | Photos, Other (messages, transcript) | Yes | App Functionality | No |
  | Identifiers | User ID | Yes | App Functionality | No |
  | Purchases | Purchase History | Yes | App Functionality | No |

  **"Data used to track you": No.** No ad SDKs, no third-party analytics, no IDFA — so no
  App Tracking Transparency prompt is required.
