## Team runbook (Supabase Studio, SQL editor — no admin screen yet)

**Approve an ambassador** (unlocks goal bonuses and cash-out; pays goals already reached):
```sql
insert into ambassador_approvals (user_id)
select id from users where email = '<their email>';
```
They must already have tapped "Become an ambassador". If they hadn't, the goals pay when they do.

**Pay a cash-out.** Pending requests: `select * from credit_cashouts where status = 'pending';`
Send the money, then:
```sql
update credit_cashouts set status = 'paid', paid_at = now() where id = '<cashout id>';
```

**Reject a cash-out** (the credit does NOT come back by itself):
```sql
update credit_cashouts set status = 'rejected' where id = '<cashout id>';
insert into credit_ledger (user_id, amount_cents, kind)
select user_id, amount_cents, 'adjustment' from credit_cashouts where id = '<cashout id>';
```

**Noot won a dispute — give the inviter's $5 back.** A new dispute takes the reward back
automatically (`reward_reversal` rows); winning does not restore it.
```sql
-- what was taken back for that booking
select user_id, amount_cents from credit_ledger
 where booking_id = '<booking id>' and kind = 'reward_reversal';
-- give it back (amount_cents above is negative, so negate it)
insert into credit_ledger (user_id, amount_cents, kind)
select user_id, -amount_cents, 'adjustment' from credit_ledger
 where booking_id = '<booking id>' and kind = 'reward_reversal';
```
The session still doesn't count toward ambassador goals (`bookings.credit_reversed_at` stays
set). If that matters for someone close to a goal, tell Claude — it needs a small code change.

**Change the goal bonuses:** edit rows in `ambassador_milestones`. Bonuses already paid aren't
changed.

## Known gaps (in the PR description too)

- Not tested on a device — in particular sign-up → emailed link → code applied.
- The server accepts an invite claim from any account that has never booked, not only brand-new
  ones (the app only offers the field at sign-up).
- An account's join date is set when its link is first requested, so someone who requests a
  link, waits, then verifies after their friend joined is refused that friend's code.
